# Settle up: payer, recipient and multiple roommates — 2026-10-10

## Changed
- Expenses now shows distinct You owe / You’re owed totals and a prominent Settle up action. One balance opens directly; multiple balances open a person sheet. Own balances remain visible; other household balances stay accessible. Existing expense creation and history preserved.
- Payment screen distinguishes Record payment sent / Record payment received; amount defaults to the actual outstanding balance. A live preview says what remains or whether that balance will be settled. Date and note are optional disclosed details. A confirmation explains money must already have moved outside Rezlee.
- Success shows the updated pair balance, who recorded the payment and a clear return action. Author/owner correction controls remain; others are told who can correct it. Unjoined participants have truthful notification limitations.
- Existing persisted save recovery, stale-balance refresh and correction history retained. A new optional expected-balance guard prevents both sides recording a partial payment from the same stale balance; exact idempotent retries remain safe.
- Shared-expense inbox/push preference and allowlisted destinations added. Recorded and removed repayments create deduplicated notices only for joined counterparties, excluding the actor and unrelated roommates. No receipt note/private original is copied into notices.
- Recipient-initiated Send reminder requires confirmation, permits only the creditor, checks current balance and joined identity, and limits a pair to once per rolling 24 hours. Retries reuse the existing outcome. Customer copy promises inbox creation, not guaranteed phone delivery.

## Preserved / removed
Existing multiple-roommate equal/exact shares, stable invite identity, author/owner permissions, pairwise balances, CAD arithmetic, private originals, existing navigation, design tokens, UI components and payment history preserved. No bank/payment integration or money movement. No auto-invites or new recipient-approval requirement. Nothing removed from customer capabilities. No unrelated Home, Bills intelligence, Vault, Care, provider, auth, website or production change. Scheduled utility pulls remain unchanged/off.

## Technical impact
One additive migration: 202610100001_shared_settlement_notices. Adds a notification preference/category, event trigger, scoped recipient resolver, reminder RPC, stale/access-loss resolution RPC and optimistic repayment wrapper around the existing ledger transaction. Existing schema fields/data remain valid. Old clients retain the existing repayment RPC contract; new clients send an optional expectedBalanceCents. Added authenticated POST /api/mobile/v1/shared-expenses/remind and optional settlementNotices capability. Existing notification worker reused; per-event claims, global/category preferences, quiet hours, token disabling and no automatic retry of uncertain push sends retained. Shared after-response dispatch is limited to the current household/category. No new package, service, cron or provider call.
